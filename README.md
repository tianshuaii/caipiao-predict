# 拾数 · 本地彩票研究室

两个独立项目：`backend/` 为 Python 3.12 + FastAPI/SQLAlchemy/APScheduler；`frontend/` 为 React + TypeScript + HeroUI。MySQL 8.4 由 Docker 管理，仅绑定 `127.0.0.1:9999`。

## 运行

已配置的本机，在项目根目录执行：

```sh
python3 scripts/local.py
```

访问 http://127.0.0.1:9998 ，接口文档 http://127.0.0.1:8000/docs 。保留终端运行，Ctrl-C 统一停止前端、API、调度器，数据库保持运行；`docker compose stop` 停止数据库并保留卷。日志位于 `runtime/`。不要重复启动同一套服务。

每天北京时间 22:30 同步开奖、核对预测、评分候选策略并生成下一未开奖期预测。预期开奖或奖金数据未齐时，于 23:00、23:30、次日 00:00 重试，完整成功后停止该批次重试。周一、三、五 08:00 只读取已保存且未过期的预测，合并推送大乐透、双色球各 5 注，不在晨报阶段重新抓取或生成号码。月初 06:00 运行探索性回测。电脑关机或睡眠期间不能执行；启动仅在对应执行窗口内补跑，不追发过期晨报。当前未安装系统登录启动项。

## 重新安装

需要 Docker Desktop、Python 3.12、Node.js 22+、pnpm。

```sh
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.lock
backend/.venv/bin/pip install -e backend --no-deps
cd frontend
pnpm install --frozen-lockfile
cd ..
```

根 `.env` 保存 `MYSQL_ROOT_PASSWORD` 与 `MYSQL_PASSWORD`；`backend/.env` 按 `.env.example` 填写 `DATABASE_URL`、`SERVERCHAN_SENDKEY`。均为本地私密文件、不进入版本控制。密钥不要出现在聊天、截图或日志中。

首次安装：启动 Docker，运行 `docker compose up -d --wait`，在 backend 目录执行：

```sh
.venv/bin/python -m lottery.cli init-db
.venv/bin/python -m lottery.cli sync --full
.venv/bin/python -m lottery.cli run
```

## 数据来源与边界

大乐透以中国体育彩票 Sporttery 官方接口为主；双色球以中国福彩网为主、上海福彩最近 100 期交叉验证，2013 年前档案使用中国福利彩票指定信息发布媒体中彩网补齐。北京福彩原站当前不可达，未伪称已从该站抓取。每次请求的来源、抓取时间、参数、原始响应和哈希入库。2026-10-23 已导入大乐透 2938 期、双色球 3518 期。部分旧期奖金缺失或含条件，显示待公布，不当作 0。

`config/calendar.json` 保存经核对的年度官方休市日历；2026 年来源为 [财政部公告](https://www.mof.gov.cn/gp/xxgkml/zhs/202512/t20251225_3980248.htm)。新年度须按官方公告补充日历；未审核年份阻断正式预测。临时调期开奖需核对更新日历及规则，不猜测期次。

## 运维与复盘

在 backend 目录：

```sh
.venv/bin/python -m lottery.cli status
.venv/bin/python -m lottery.cli run --no-notify
.venv/bin/python -m lottery.cli replay 1
.venv/bin/python -m lottery.cli backtest --game all --periods 60
.venv/bin/python -m lottery.cli notify 1
```

`run` 和兼容参数 `run --no-notify` 均只采集、结算与预测，不创建通知或调用推送通道；它们仍会访问官方数据源并写入数据库。定时晨报单独处理通知。同期号码不可覆盖，通知按报告内容去重。`sent` 仅代表通道受理；`uncertain` / `sending` 必须先核实微信，程序不会盲目重发。历史预测、中奖核对均为模拟，不代表已购票或实际到账。

备份（项目根目录）：

```sh
python3 scripts/backup.py --verify
```

保存 SQL 与预测/实验快照到 `backups/时间戳/`；`--verify` 恢复到全新的 `lottery_restore_...` 库并核对记录数，不覆盖运行库。恢复库保留供检查。生产恢复应先停止所有服务、另建库导入 SQL、恢复 artifacts 后更新 DATABASE_URL，核对通过再切换，勿直接覆盖现有数据库。备份包含业务记录，应妥善保管。

## 整组目标与同期随机对照（2026-10-26，已部署）

策略实验室新增三类独立目标：每期5注中至少一注中任意奖、至少一注中一等奖、模拟净收益及ROI（净收益÷成本）。正式建议与候选版本分别统计，按彩种、策略版本、开奖奖金规则版本拆分。历史观测比例不是未来中奖概率。

新预测生成时提前冻结100组独立随机对照，每组5注，保存专用随机种子、号码、截止时间和协议版本。重复执行不覆盖，不为已开奖期补造对照；各组内去重，各组之间允许重合。对照不进入正式推荐或微信推送。

对照比较只匹配双方同一期有效记录。100组分别跨匹配期次累计，再展示2.5%、50%、97.5%分位数：这是随机轨迹的分布范围，不是置信区间，也不能把100组当成100倍独立开奖样本。收益比较额外要求策略与全部对照奖金完整；未知金额不视为零。官方更正按新指纹评分，历史评分保留，页面只使用当前无冲突版本。

这批目标统计不会改变原有Brier前瞻晋升门槛，不自动追逐短期中奖或收益。新增迁移003（random_controls、control_scores），已在本地和云端MySQL应用。

## 一等奖中奖彩票案例库（2026-10-26，本地新增，尚未部署）

前端“一等奖票型”页按彩种、票型筛选公开报道案例，支持分页、原文证据、来源日期、抓取时间、原始响应编号和报道图片链接。字段包括单式注数、倍数、复式规格、展开基本组合数（不含倍投）、明示投入、明示一等奖注数、追加及报道奖金文字。缺失值保留未知，图片未做OCR，自动抽取不等于人工确认。胆拖细节保留原文，不反推选号。

```sh
backend/.venv/bin/python -m lottery.cli init-db
backend/.venv/bin/python -m lottery.cli cases --limit 20
# 指定白名单内的官方历史报道（可重复指定 --url）
backend/.venv/bin/python -m lottery.cli cases --url 'https://www.js-lottery.com/xwzx/zdgz/cms/post-147033.html'
```

默认从三个已核验种子报道和江苏体彩、广东福彩新闻列表发现链接；单次最多100篇（默认20）。当前是有界采集与指定URL导入，不宣称已采集全历史，也未接入每日预测调度。默认列表可能含只有图片或未明确票型的报道；已识别的图片票保留为待核对。可识别正文变化会保留旧案例但停用，原始响应仍留存。

新增只读接口 `/api/winner-cases?game=dlt&ticket_type=all&offset=0&limit=20`，迁移004创建winner_cases表。初始导入8条案例记录，包含7条大乐透、1条双色球；这不是独立中奖票数量。全国/地区一等奖汇总段落不作为单票案例，不把一等奖中奖注数误当投注注数。跨文章同票可能重复，不统计全量票型中奖率，不进入预测或晋升。

## 指标组合候选策略（2026-10-26）

每彩种14种候选，每种每期5注，共70注测试；正式推荐与微信仍各彩种5注。策略内部去重、跨策略允许重合；多注不是多个独立前瞻期次。

- 单频率、基础逻辑回归：保留原有对照。
- 频率＋奇偶、频率＋大小、频率＋三区、频率＋质合。
- 频率＋遗漏、频率＋奇偶＋遗漏。
- 频率＋组合结构：联合奇偶、大小、三区、质合。
- 频率＋数值：上期和值、跨度、均值、AC、尾数和及交互项。
- 频率＋关联：重号、邻号、同尾、历史相邻/同尾/二码共现。
- 全指标联合：同时使用以上可从开奖数据计算的特征。

指标组合逻辑回归模型以基础逻辑回归为基础，使用近30/100期频率、上一期是否出现，联合新增特征及其与频率的交互项。最多用300期历史，最后30期按时间顺序校准。每个训练目标仅使用其之前的历史；奇偶等描述的是历史结构上下文，不硬性限定推荐号码的比例，也不是整注联合概率模型。

遗漏统计限定训练窗口：当前遗漏=末次出现后未开期数；最大/平均遗漏只计两次出现之间已完成的间隔；最近周期=最近两个出现位置之差。未出现及无完整周期分别标记。大小按各区号码上限的一半划分；三区按号码序号等分；1不归为质数或合数。AC为不同正差值数量减去球数减1，单球区为0。

投注热度、组合购买热度、投注重复率、机选占比没有可靠数据，未纳入。当前用概率评分决定晋升，整组中奖及收益继续独立报告，不把指标增加解释为中奖率提升。

算法/特征文件纳入版本哈希；本次更新后当前版本均重新积累前瞻证据，旧数据仍保存。重启使用新代码的后端后，在下一次合法开奖前生成流程登记候选，已冻结正式号码不会被覆盖。离线测试和历史回测不计入前瞻样本。

### 全指标非线性候选

新增 `forest_all`（随机森林）与 `neural_all`（小型神经网络），使用与 `freq_all` 完全相同的历史特征、300期训练窗口、最后30期校准段和每期5注预算。随机森林64棵树、深度4、最小叶节点30、单线程；神经网络单隐藏层16节点、tanh激活、L2正则alpha=10、LBFGS最多500次迭代、固定随机种子，不使用随机早停验证集。

两者用预测概率的logit在后续30期校准，再约束各区概率和。训练未收敛记为候选失败，不沿用失败结果或阻断其他策略。新版本单独积累前瞻证据，正式推荐数量与晋升门槛保持不变。尚无证据表明它们提高中奖率。

本地验证：84项后端测试、2项前端测试及生产构建通过；冻结历史样本离线生成每彩种14组70注，本机耗时约1.6秒（不是云端性能承诺或前瞻评估）。本次未写业务数据库、未发送通知、未部署云端；新代码加载后由下一次合法预测流程登记新候选。
