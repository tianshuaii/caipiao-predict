# 彩票分析平台重构任务清单

更新时间：2026-10-26。状态：M1（T01—T05）已在本地完成；T06—T30待实施，云端未部署。

依据：[原始需求参考](requirements/lottery-platform-reference.md)、[现状核对报告](reports/2026-10-26-feature-audit.md)及用户后续确认。本文是待办与验收清单，不代表功能已完成或已部署。历史开发计划继续作为记录，不覆盖。

## 1. 范围与不可改变的业务约定

- 采用渐进式重构；保留 React + TypeScript + HeroUI + Recharts、FastAPI + SQLAlchemy + MySQL。保持前后端两个项目，不为匹配参考文档更换技术栈或拆微服务。
- 本轮排除「彩民行为研究」：不开发投注热度、选号偏好、授权选号样本、撞号风险与分奖人数估计。现有一等奖票型报道保留，但不当作全国投注数据。
- 支持双色球、大乐透。现有14种候选作为回归基线，每种每彩种每期5注，候选共70注；跨策略允许重合、策略内去重。正式建议仍为每个彩种每期5注单式。
- 北京时间每天22:30抓取并分析；未齐于23:00、23:30、次日00:00重试。周一/三/五08:00合并发送两彩种已冻结的有效正式推荐。
- 未通过前瞻门槛保持随机基线，历史回测不触发晋升。现有至少60期、概率评分改善、近期表现、持续证据门槛及回退保护继续保留；如要改变需另立实验协议。
- 已冻结的正式预测与候选不重写。结构性重构不能无理由重置证据；特征、算法或影响结果的参数变更必须产生新实验版本。
- 模拟复式/胆拖、任意研究注数不改变正式晨报5注约定，不接入真实购彩和支付。
- 本地实现与云端发布分开验收。本清单不授权立即修改云端、发送通知或迁移生产数据库。

## 2. 当前可复用能力

已有：官方采集与补缺、原始响应、期号覆盖及冲突检查、按规则结算、预测快照与种子、候选前瞻评分、100组同期随机对照、14种候选、定时流程、晨报、基础看板和中奖案例。它们是迁移保留对象，不是新建任务。

现有测试基线：最近一轮84项后端测试、2项前端测试及生产构建通过；开始重构时须重新验证。最新新增策略尚未部署云端。

状态定义：所有未勾选任务均待实施；只有功能、测试、文档和验收证据齐备后才勾选。P0为基础/可信性，P1为核心完整性，P2为后续实验能力；优先级不替代依赖顺序。

## 3. 执行任务

### 阶段A：业务基线与数据安全

- [x] T01【P0｜保留】建立行为回归基线
  - 依赖：无。涉及：backend/tests/、frontend/tests/、docs/verification.md。
  - 工作：固定两彩种规则边界、14候选、5注正式建议、时间窗口、重试、通知幂等、开奖修订、失败回退和截止后禁止生成等场景。
  - 验收：用隔离数据重跑基线；保存API响应及固定种子号码样例，后续重构可比较；不得实际发送微信或写业务库。

- [x] T02【P0｜设计】确定模块接口与迁移边界
  - 依赖：T01。涉及：backend/lottery/、frontend/src/api.ts、docs/。
  - 工作：定义数据/规则、特征、模型、选号、评估、调度的输入输出与版本责任；逻辑回归等为模型，频率/全指标为特征方案，加权/约束为选号方法，三者组成实验。
  - 验收：现有14候选逐一映射到新实验配置；原有API有兼容或分阶段迁移方案；不复制出14套训练代码。

- [x] T03【P0｜迁移】建立增量迁移和恢复流程
  - 依赖：T02。涉及：backend/migrations/、deploy/backup.sh、恢复测试。
  - 工作：在数据库副本演练备份、增量迁移、行数/关键字段校验、失败恢复；保留原始抓取、观测、预测、评分、对照和决策记录。
  - 验收：迁移前后已冻结票组、快照哈希、结算一致；恢复演练通过；无删库重建要求。

- [x] T04【P0｜重构】统一规则和结算服务
  - 依赖：T01、T02。涉及：domain.py、workflow.py、prospective.py、portfolio.py、experiments.py。
  - 工作：正式预测、候选、随机对照、历史回测共用奖级与奖金处理逻辑；显式记录规则版本和缺失奖金。
  - 验收：适用期号边界及各命中组合通过测试；未知奖金不按0处理；所有调用方对同一票给出同一结果。未覆盖玩法/活动必须明确标注。

- [x] T05【P0｜增强】完善数据质量与历史可见性
  - 依赖：T03。涉及：collectors.py、ingestion.py、models.py、api.py。
  - 工作：分别展示号码覆盖、奖级字段完整率、来源冲突和时效；保存观测/修订时间，支持按历史可见时点选取数据。
  - 验收：修订不覆盖原始证据；回测可区分“当前修订数据”与“当时可见数据”；无法补回旧观测的年份明确标记，不伪造历史时点完整性。

### 阶段B：特征、模型与选号解耦

- [x] T06【P0｜重构】建立特征目录和统一计算接口
  - 依赖：T02。涉及：indicators.py、新特征服务、指标API。
  - 工作：每个指标登记ID、定义、窗口、适用区、空值语义、版本和依赖；页面、训练、回测复用同一计算逻辑。
  - 验收：输入数据截止期明确，任何目标期以后的数据变化不影响特征；分类编码/交互项不重复计算为独立指标数量。

- [x] T07【P1｜新增】补齐基础指标及多窗口
  - 依赖：T06。涉及：特征服务、指标测试与API。
  - 工作：支持10/20/30/50/100/500期及有意义的全历史窗口；次数/频率、冷热排名、当前/最大/平均遗漏、遗漏标准差、重复周期分布和频率Z分数。
  - 验收：无历史/短窗口/未出现/跨年均有明确结果；完成间隔与未结束遗漏区分；与手工样例一致。排名与Z分数不被描述为下一期概率。

- [x] T08【P1｜新增】补齐组合、数值和关联指标
  - 依赖：T06。涉及：特征服务、组合分析API。
  - 工作：奇偶/大小数量及连续性、三区/四区和密度；和值/均值/中位数/方差/跨度；尾数分布/尾数和/同尾；连号组数/最大长度/间隔；重号/邻号/重尾/上期差；AC/互异差值/明确定义的组合熵；质合/012路；二码/三码共现及明确分母的条件频率。
  - 验收：各区边界固定，1的质合分类明确，单球区不适用指标有约定；超小样本和稀疏共现不产生虚假确定性；每项有公式、样例和一致性测试。

- [x] T09【P0｜重构】统一模型接口与训练产物
  - 依赖：T02、T06。涉及：experiments.py、prospective.py、模型存储与迁移。
  - 工作：抽离fit/predict/calibrate接口；统一登记训练窗口、参数、特征版本、随机种子、预处理器、模型、校准器与依赖环境；接入现有频率/逻辑回归/随机森林/MLP。
  - 验收：加载保存产物后复现预测概率；时间顺序校准隔离；训练失败独立记录；只加载本系统可信产物，不执行任意上传模型文件。

- [x] T10【P0｜增强】稳定实验版本与证据继承
  - 依赖：T03、T09。涉及：prospective.py、版本注册、迁移测试。
  - 工作：替代“改任意共享文件就重置所有模型”的粗粒度版本方式；用明确影响输出的实验配置与实现版本登记。
  - 验收：仅目录重排且结果一致的重构保留版本关联；实际算法变化创建新版本并分配新检验预算；旧评分不嫁接到新算法，旧决策可追溯。

- [x] T11【P0｜重构】分离选号引擎并明确概率语义
  - 依赖：T02、T09。涉及：predict.py、experiments.py、重放CLI。
  - 工作：统一组合生成接口、种子与数量校验、批内去重；区分号码预测边际、抽样权重与实际入选边际；为需要精确边际的策略选定并记录合适抽样协议。
  - 验收：合法票组/固定种子重放/抽样频率验证通过；不把权重归一化抽样宣称为精确实现模型边际；旧票仍可按原协议重放。

- [x] T12【P1｜新增】约束选号与研究配置
  - 依赖：T08、T11。涉及：选号服务、API、前端配置页面。
  - 工作：可选奇偶、分区、和值、跨度等约束；有限候选池、研究注数与模拟成本预览、去重；保存配置与结果。
  - 验收：约束无解能说明原因并停止，不无限重试；每注满足配置；研究保存与正式推荐分开，不改变晨报5注。

### 阶段C：评估可信性与统计中心

- [x] T13【P0｜重构】统一回测和前瞻评估记录
  - 依赖：T04、T05、T09、T10、T11。涉及：experiments.py、prospective.py、portfolio.py、models.py。
  - 工作：共享预测/结算协议，分别保留历史回测与真实前瞻标记；保存逐期票组、奖级、金额、截止和失败状态；模型比较限定共同有效期次及同预算。
  - 验收：目标期信息不能进入训练；失败期/奖金未知期不静默当作0或选择性丢弃；回测不能填充前瞻样本。

- [x] T14【P1｜新增】完整模拟绩效指标
  - 依赖：T13。涉及：评估服务、portfolio.py、实验API。
  - 工作：奖级次数、中奖期数、成本/奖金/ROI、累计净收益曲线、资金曲线和最大回撤；分别统计任意奖、一等奖和收益。
  - 验收：最大回撤的金额/比例定义及初始资金明确；零成本/未知奖金正确处理；按彩种/规则/实验版本分组，人工样例可核对。

- [x] T15【P0｜新增】不确定性与随机对照评估
  - 依赖：T13、T14。涉及：统计评估服务、测试、展示字段。
  - 工作：中奖率区间、配对超额表现区间、适用的Bootstrap/分块Bootstrap；保留100组同期随机对照和分位数；记录抽样单元、方法、种子和样本数。
  - 验收：整期或时间块重采样，不能把同一期5注当5个独立样本；零一等奖/少样本不输出虚假精度；明确随机分布、参数置信区间、未来预测区间的区别，并说明稀有巨奖收益区间局限。

- [ ] T16【P1｜新增】平台化统计检验中心
  - 依赖：T05、T06、T08。涉及：scripts/analyze_randomness.py迁移入口、统计服务、结果API。
  - 工作：接入理论分布对照、适当的卡方/模拟拟合检验、自相关、游程、蒙特卡洛、多重检验及漂移诊断；保存数据快照、预设检验族、结果和事后分析标记。
  - 验收：同期开奖不放回约束进入零假设，不能默认各球独立；跨窗口探索与规则变化明确标注；已知模拟随机数据/人工偏差数据验证误报与检出行为。

- [ ] T17【P1｜新增】可解释的策略排行
  - 依赖：T13、T14、T15。涉及：策略API与排行榜页面。
  - 工作：按统一期次/预算展示模型评分、任意奖、一等奖、收益、区间及样本量；支持不同目标切换。
  - 验收：样本不足明确标识；排行榜不自动替代前瞻晋升门槛；候选排序理由可查，不把上期赢家当下期最优。

### 阶段E：模拟管理与运行保障

- [ ] T22【P1｜新增】复式、胆拖与组合计费
  - 依赖：T04、T11。涉及：玩法/组合服务、模拟API及前端。
  - 工作：单式/复式/胆拖合法性、组合数量、单式展开和模拟成本；大乐透追加作为明确选项单独定义规则，不隐式启用。
  - 验收：组合数与枚举一致、胆码拖码不重叠；超过上限拒绝或采用有说明的计算方式；逐注结算与展开总额一致，正式推荐仍5注单式。

- [ ] T23【P1｜新增】虚拟预算与模拟追号
  - 依赖：T14、T22。涉及：模拟账户/记录、前端模拟管理。
  - 工作：初始虚拟资金、预算上限、期数、止损/停止条件、复式及追号模拟、资金流水。
  - 验收：仅虚拟交易、可重算和审计；余额不足停止；不因收益目标擅自增加正式推荐注数。

- [ ] T24【P0｜增强】任务可靠性与主动告警
  - 依赖：T01、T05、T09。涉及：scheduler.py、workflow.py、notify.py、任务日志。
  - 工作：训练/回测状态与耗时、来源异常、缺期、模型失败、磁盘/数据库/调度失联监测；失败告警去重与恢复通知；与普通晨报分离。
  - 验收：故障注入后有可追溯记录；告警不含密钥、不刷屏；未获独立发送授权的开发测试使用模拟通知，不真实发送。

- [ ] T25【P0｜新增】真实管理权限与配置保护

### 阶段F：可选模型扩展与发布验收
