# 虚拟账户与历史追号

在「组合模拟」先计算固定票组，再填写起始历史期号、期数（1–30）、初始资金、总支出预算、可选累计亏损上限与中奖停止，管理员点击保存。每次保存是独立虚拟账户，所有历史列表公开读取。不会实际购买、充值、提现或改变正式推荐。

累计亏损＝初始资金－当前已确认余额。购票前按整期零奖金预留成本，不突破亏损上限；这不是从资金峰值计算的回撤。预算限制累计支出，奖金不增加预算。余额不足不允许透支，任意奖停止在该期结算后生效。

当前范围为固定组合的历史追号模拟，不跟随候选策略、不自动跟踪未来开奖、不倍增投注。最多20000个单式期次结算，避免长计算阻塞；所有金额使用Decimal。账本包括初始资金、逐期模拟支出、已确认奖金和余额。

按期号要求同一年连续。缺期、冲突、跨年、未知奖金均停止，未知奖金不填零，净收益为空；显示余额是已确认下界。跨年需另建模拟。停止原因还包括期数、预算、余额、亏损和中奖。未购票的期次没有资金流水。

保存冻结配置、当前修订开奖快照、指纹、结果、快照/结果SHA256及模拟版本。开奖后续更正不影响旧模拟。重放使用冻结快照、校验版本及哈希，比较新结果，不写回旧记录。代码算法变化应升级模拟版本；该历史模拟不能充当前瞻验证成绩。

接口：POST `/api/simulations`（管理员会话、Origin、CSRF保护）；GET `/api/simulations` 分页；GET `/api/simulations/{id}` 详情；GET `/api/simulations/{id}?replay=true` 只读核对。未知ID返回404，完整性/版本失败返回409。

启用前在目标环境执行 `backend/.venv/bin/alembic -c backend/alembic.ini upgrade head`（沿用项目数据库配置，部署时按既有迁移流程）；本轮仅对隔离SQLite测试执行008迁移，未迁移本地业务库或云端。
