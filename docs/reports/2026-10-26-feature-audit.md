# 项目特性核对报告

核对对象：用户提供的“完整双色球＋大乐透AI平台”清单。范围为2026-10-26本地代码、配置、测试定义及此前生成的审计产物。未连接云端、未实时查询业务库完整率、未重新抓取官方数据。本次仅检查并写报告，没有增加业务功能。最近一轮开发验证为84项后端测试、2项前端测试和构建通过；测试通过不能替代完整业务验收。

## 指标逐类核对

不能将特征矩阵的列数当作“60项独立统计指标”：分类编码、交互项和冗余指标都会增加列数。

| 清单指标 | 本地情况 |
|---|---|
| 多窗口出现次数/频率 | UI最近20期；基础模型30/100期及频率模型100期；无10/50/500/全历史任意窗口分析接口 |
| 当前/最大/平均遗漏、周期 | 在300期训练窗口内计算；已完成间隔统计、未出现/无完成周期标记；不是全历史遗漏 |
| 遗漏标准差、完整周期分布 | 未实现为独立分析指标 |
| 热度排名、频率Z分数 | 无平台功能；离线审计有高低频描述和精确检验，但不是相应UI |
| 奇偶/大小/三区/质合 | 有类别成员、最近组别频率、上期组别数量和交互；1单列；无连续奇偶/大小游程与四区分析 |
| 和值、跨度、均值、AC、尾数和 | 模型使用上期上下文及与号码位置/奇偶交互；UI有20期和值图；不是全部候选组合的逐注约束/评分 |
| 中位数、方差、组合熵、012路 | 未实现 |
| 重号、邻号、同尾、二码共现 | 有模型特征及部分离线检验；不是完整的条件概率查询引擎 |
| 连号 | 有历史相邻共现特征与离线连号对分布检验；没有完整连号组数/最大长度分析页面 |
| 三码共现、完整尾数分布/重尾/上期号码差 | 未实现为独立完整指标 |

## 统计与模型

- M0随机基线：有。M1统计模型：有平滑频率，复杂指标主要是学习特征，非传统固定筛选规则引擎。
- M2机器学习：有逻辑回归、随机森林；无XGBoost/LightGBM。
- M3序列深度学习：没有。现有MLP单隐藏层16节点，不应称为LSTM或Transformer。
- M4跨模型集成：没有。随机森林内部集成多棵树，不等于融合现有候选模型；正式策略是选一个合格候选。
- 所有候选输出号码边际预测，满足双色球红球和为6/蓝球和为1，以及大乐透前后区和为5/2；组合生成保证范围和不重复。
- 重要边界：将预测p归一化成权重后做不放回抽样，不保证组合生成器的实际入选边际概率恰好等于模型p。当前是概率评分＋加权选号，不是完整一致的联合分布模型。
- 多候选Holm用于探索性回测；前瞻使用按版本分配预算的e-process。分配按彩种进行，不能宣称已对两个彩种和所有历史研究统一控制全局错误率。
- 离线审计有精确二项频率/共现检验、超几何重号分布、和值/奇偶/连号分布模拟、5段同质性检验；不是一般自相关/游程/Bootstrap/实时漂移中心。
- 100组随机轨迹的2.5%/50%/97.5%分位数是参考分布，不是策略收益或优势的置信区间。

## 回测与溯源验收

| 验收项 | 结论与限制 |
|---|---|
| 数据完整可追溯 | 有覆盖检测和来源记录，但号码覆盖与奖金完整度分开；本次未查询当前库状态 |
| 任一期预测还原 | 保存概率、种子、数据快照和哈希、版本、截止期、生成时间；replay重建号码并验证快照。没有完整持久化训练权重、预处理器和校准器，旧版本源码/依赖也未做完整模型注册表归档，不能保证任一旧模型重新训练复现 |
| 同期同预算随机比较 | 前瞻有100×5注对照，按相同期次匹配；奖金比较仅双方完整期次；回测同5注。不同模型版本如覆盖期次不同，不能直接横向把全样本汇总当同样本比较 |
| 规则版本 | domain.py按彩种和期号分支，金额来自当期开奖数据，测试覆盖规则边界；目前单式基础投注，未覆盖任意复式、追加、胆拖及全部促销情形 |
| 开奖后不修改预测 | 正式/候选有唯一键、截止检查、已有预测直接复用；开奖修订对应新的评分记录。是应用层冻结，不是数据库层不可篡改存储 |
| 不确定性说明 | 有待定奖金、随机分位数说明、未达标回退、概率评分不等于中奖率提示；没有完整CI体系 |
| 没有优势明确报告 | 有保留均匀基线及证据不足原因；Brier优势不是整组中奖概率优势，中奖/收益指标目前不触发晋升 |
| 历史回测防未来数据 | 训练只取目标期前开奖记录，按时间校准；但现在回测读取当前修订后的历史记录，未完整重建当年每个时点的原始可见版本，属于额外限制 |
| 完整逐期回测结果 | 文件保存逐期概率和票组，数据库存汇总；非独立规范化逐期奖级/资金曲线表和UI |

## 技术栈、数据库、页面

实际是React19＋TypeScript＋HeroUI＋Recharts、Python FastAPI＋SQLAlchemy＋APScheduler、NumPy/SciPy/scikit-learn和MySQL；没有Spring Boot/MyBatis-Plus/Redis、Ant Design/ECharts、XGBoost/PyTorch。这是实现选型差异，不应直接等同业务功能缺失，不建议仅为符合示例重写。

已有原始抓取、开奖、来源观测、预测、结算、任务、通知、实验、候选/评分/切换、随机对照、中奖案例等表。开奖与奖金等使用JSON保存，快照/回测产物落本地runtime文件，不是对象存储。规则和策略参数在代码中；没有独立特征仓库、模型训练产物注册表、授权用户选号样本表和模拟账户体系。用户清单的表名不是必须一一对应的验收标准。

前端实际6个入口：数据概览、开奖档案、预测与复盘、策略实验室、一等奖票型、运行记录。有频次色块和和值曲线；没有遗漏热力图、模型收益资金曲线、随机分布可视化图。历史接口可按具体期号查详情，列表支持分页；没有完整UI多条件筛选。没有训练参数编辑、交互选号配置器、真正管理权限；当前是假登录，后端接口不受其保护。

## 优先补齐建议（本次不实施）

1. 统一评估：中奖/ROI置信区间、资金曲线、最大回撤、奖级累计统计；保持同规则同期同预算。
2. 溯源与可靠性：模型及校准器持久化、历史源码/环境归档、显式版本注册、历史时点数据重建、失败主动告警。
3. 分析体验：多窗口指标接口、遗漏热力图、收益曲线和随机分布图，清楚展示指标定义和适用窗口。
4. 策略配置：组合约束、复式/胆拖与预算模拟；同时解决模型边际与组合抽样分布一致性。
5. 只有获得合法可靠样本后再开展彩民偏好/撞号研究；增加深度模型或改写Java架构不是当前完整性的首要缺口。

云端状态：最近新增指标策略、随机森林、神经网络均按用户范围只改本地；本报告不能作为云端已具备这些功能的证明。
