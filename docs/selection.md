# 选号协议与概率语义（T11）

统一入口：`selection.select_tickets(game, seed, count=5, protocol=..., probabilities=...)`。
彩种ssq/dlt；非负整数种子；1–10注。正式建议仍为每彩种5注。输出验证号码范围、区内唯一、每批整注唯一，不返回不完整票组。

## 三种当前协议

| 协议 | 输入 | 含义 |
| --- | --- | --- |
| uniform-checked-v2 | 无概率向量 | Python random.sample，均匀抽样；批内去重 |
| weighted-checked-v2 | 非负有限权重，两区维度正确 | 归一化后按NumPy顺序不放回抽样，批内去重；输入不是实际入选边际 |
| systematic-marginals-v1 | 每项在[0,1]、每区总和等于选球数的边际向量 | 单注精确边际系统抽样，只支持count=1 |

模型概率是对下一期开奖单号是否出现的估计。正式候选选号将它用作抽样权重；不承诺被选进建议票的频率与这个模型输出相等。校准概率或获得Brier优势，也不直接证明整注中奖或收益优势。

例如不放回选2个号码，权重[0.8,0.7,0.5]之和为2，首号实际入选概率约0.7487，并非0.8。批内去重还会影响后续票的条件分布。

精确单注协议：令累计边际为C_i，抽取U~Uniform[0,1)，在U+j（j=0..k-1）落入的累计区间选号码。每个区间长度<=1，获得k个不同号码；每号被选概率等于其区间长度。浮点总和容差1e-10。号码按固定顺序排列，协议保证边际，不保证所有组合或号码对等概率；它不是现有候选自动采用的新模型。

任意给定边际下，不能未经证明地保证多注去重后仍精确。因此当前精确协议只接受单注研究，未用于晨报5注或策略晋升。

## 边界与追溯

- 加权入口拒绝NaN/Inf/负数、错误长度、零和及不够选球的支持集。
- 两区支持组合数不足以生成请求注数时直接拒绝。
- 最多尝试2000张候选；极端集中权重无法形成足够唯一票时明确失败，不无限循环、不偷偷改为均匀分布。
- 候选失败按现有流程记录，其他模型继续，正式推荐可回退均匀基线。
- 正式预测和候选provenance保存selection，包含协议、输入语义、实际入选语义、批去重和尝试上限。回测报告明确均匀/候选/对照协议映射，每组预测保存独立协议、种子及概率语义，可按记录重放。新随机对照使用matched-uniform-100x5-checked-v2。

## 版本与旧数据

旧 `generate_tickets` / `weighted_tickets` 内核原样迁入selection模块并兼容导出，仅供可信旧记录重放。CLI `replay` 优先读取记录协议，旧记录无协议时按uniform-v1或旧加权规则推断。原90组加权及6组均匀黄金票组已验证一致。

新受校验入口增加重试预算及失败条件，因此登记为新协议，新候选使用新实验身份并重新积累前瞻证据；不会把旧评分嫁接过去。正式uniform-v1表示基线策略族，具体选号实现由selection.protocol记录。已有冻结票组及旧评分不重写。

注册器仍可描述旧选择协议，其14个身份别名保持。模型产物头保存选择协议，旧T10头缺少该字段时按旧选择协议验证；T09更早格式仍走旧严格实现检查。
