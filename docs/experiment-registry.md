# 实验版本与证据继承（T10）

每种候选使用独立实验配方。`experiment_registry.describe(strategy)` 返回完整描述，`fingerprint(strategy)` 返回SHA256，`registered_versions()` 返回生产候选身份。

配方包含：策略名、实际训练窗口/种子/研究注数/校准窗口、特征组合及版本、相关函数实现摘要、选号协议、区内号码范围、依赖环境，以及评分/结算/前瞻门槛、样本汇总、显著性预算分配和策略切换实现及参数。

## 哪些变化保留身份

- 函数源码只改变注释、docstring、空白或文件位置，不改变AST；身份不变。
- 不参与生成或评分的介绍文案变化，不影响身份。
- 调整森林构造参数只更新森林身份；修改某一个策略的特征组合只更新该策略。
- 训练公共流程、共享特征计算、评分门槛等相关逻辑变化会更新所有依赖它们的配方，保守防止误用旧证据。

AST归一化不识别任意语义等价重写。重命名调用、修改import路径等可能产生新摘要，需要人工验证，不自动宣称等价。依赖环境更新也保守产生新身份。

## 旧证据与新版本

T10改动前后的黄金概率样例一致。当前14个初始配方hash一次性登记为旧身份别名，保证原评分和检验预算关联不被目录重构打断。此映射不在运行时重新生成，也不能把新算法hash加入旧身份别名以继承旧评分。

其他hash使用 `策略名-v2-前32位hash`，适配既有60字符数据库字段；完整SHA256随配方存储。新身份继续通过现有前瞻流程分配独立检验预算，不复制历史评分。历史回测不充当前瞻样本。

每个新候选（包括训练失败）在provenance保存 `experiment` 与 `experiment_hash`；成功候选的模型产物也保存同一配方。已经冻结的候选不重写，历史决策继续引用当时的候选身份。

## 训练产物兼容

新产物加载前比较所属策略的实验hash，因此无关模型变化不会阻止其重放。依赖环境与完整文件哈希检查仍保留。
T09旧产物缺少配方字段，继续执行原严格实现指纹检查；需要旧实现时使用原环境重放，不自动迁移pickle。格式和候选身份兼容是两个不同问题。

本阶段没有数据库表迁移、云端部署或通知。T09超时训练留下无引用产物的清理事项仍待后续处理。
