# 独立运行监控

本地检查（不发送通知）：

```sh
backend/.venv/bin/python -m lottery.cli monitor
```

持续监控（每轮后等待60秒，不发送）：

```sh
backend/.venv/bin/python -m lottery.cli monitor --watch
```

部署时确认要实际推送后，显式增加 `--send`，读取已有Server酱配置。必须用独立systemd服务或独立容器守护，不能放进被监控的scheduler进程。本轮未启动监控或启用真实发送。

检查内容：数据库连接/读取、运行目录磁盘余量至少1GiB、调度心跳小于120秒且不来自未来、最近夜间任务26小时内且成功（运行中宽限1小时）、采集交叉校验异常、最新数据待齐、两彩种历史覆盖、各彩种最新期候选错误、每模型研究任务失败或排队/运行超过1小时。研究耗时显示在模型中心详情。夜间任务运行中来源/最新数据检查为未知，不提前报错；数据库不可用时相关检查为未知，原故障状态保留，不报恢复。尚无完整历史或尚未配置调度器会显示异常，不隐藏初始化状态。

状态/最近200事件保存在 `runtime/monitor.json`，文件锁防止多进程同轮操作，临时文件原子替换。故障持续期间不重复生成事件，恢复生成一次独立事件。相同故障恢复后再次发生会产生新事件。记录只使用固定检查项名称和状态，无原始异常、地址、凭据。与晨报通知表和发送流程独立，不改变晨报。

推送前保存sending状态。响应不确定、进程中断、失败、未配置均不自动重发，避免重复通知；请人工核对。未启用发送期间的历史事件不会在后来开启时补发，开启后仅发送新状态变化。清除状态文件会丢失去重记忆，禁止常规清空。

只读 `GET /api/monitoring` 与运行记录页展示状态，超过180秒标记过期。数据库故障时监控页仍可单独读取本地状态。状态损坏返回503，不自动覆盖。若监控文件无法写入，不发送通知以避免无持久记录的重复推送。

限制：这不是外部可用性监控。同机断电、整个容器停止、监控自身阻塞/退出无法自行通知，需主机外探测补足；磁盘完全不可写也无法保存或发送可靠事件。数据库超时针对当前MySQL/PyMySQL和SQLite配置，其他驱动需单独配置。不会自动杀任务、补采或重跑模型。
