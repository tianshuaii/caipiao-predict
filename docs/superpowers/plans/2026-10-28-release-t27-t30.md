# T27--T30 release plan

## Goal

Finish the two bounded research experiments, verify the full release path in an
isolated environment, then upgrade the existing Huawei deployment without
changing frozen forecasts or sending an extra notification.

## Acceptance path

1. Add one low-memory tree-boosting candidate and one fixed, documented
   probability blend.  Verify valid marginals, chronological calibration,
   separate experiment identities, and five-ticket candidate output.
2. Record a reproducible sequence-model feasibility decision.  The 2-core,
   2-GB deployment target must not gain a heavyweight runtime unless a
   time-split comparison demonstrates a reliable benefit.
3. Repair the disposable migration rehearsal for the current Alembic head and
   include all runtime research artifacts in backups.
4. Build the Linux image and frontend, rehearse the database upgrade, and
   collect local resource/functional evidence.
5. On the Huawei host: create and checksum a backup, stage the verified
   release, run additive migrations, restart services, and verify health,
   authenticated UI, scheduler and worker status.  Do not run a workflow or
   send a notification as part of deployment.

## Constraints

- Existing frozen predictions, candidate forecasts, scores and version
  identities remain immutable.
- New candidate versions start with no prospective evidence and cannot become
  the formal strategy through historical backtests.
- The blend uses a pre-specified equal weighting of component probabilities;
  its parameters are not selected using target or future draws.
- No XGBoost, LightGBM, PyTorch, TensorFlow, LSTM or Transformer dependency is
  added for this bounded experiment.
- Cloud secrets remain on the server and are never copied into source control
  or command output.
