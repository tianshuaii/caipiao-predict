# 四彩种统一分析与正式预测设计

## 意图

将双色球（ssq）、超级大乐透（dlt）、七乐彩（qlc）和七星彩（qxc）接入同一套可审计的开奖数据、指标分析、候选模型、组合生成、回测与前瞻评估体系。用户可查看研究输出；正式推荐仍只在候选通过独立前瞻证据门槛后切换，不能由历史回测直接决定。

本设计以“统一能力、保留历史”为目标：既有双色球/大乐透开奖、预测、结算、策略版本、候选评分和决策记录均不可被重写或重新解释。

## 目标与非目标

### 目标

- 四彩种均具备六层能力：基础开奖数据、统计指标、高级特征、候选模型、组合优化、回测/前瞻复盘。
- 为七乐彩支持 30 选 7 基本号与 1 个特别号；基本号和特别号在数据、特征、概率、选票与结算中独立处理。
- 为七星彩支持七个有序数字位置：位置 1--6 的取值域 0--9，位置 7 的取值域 0--14；2020-10-11 起的新规则数据与此前规则严格分版本隔离。
- 使用官方公开来源作为主源，至少一个独立公开来源作交叉核对；原始响应、解析版本、规则版本和来源都保存。
- 新模型以时间顺序滚动回测产生研究证据，并以冻结的上线后前瞻预测作为唯一正式晋升依据。
- 所有正式预测固定为每期 5 注、每注 2 元；组合生成在相同预算内去重并度量覆盖与相似度。

### 非目标

- 不宣称任何统计指标、模型或回测能提高未来理论中奖概率。
- 不将 LSTM/Transformer 作为默认生产模型；仅在有明确、可复现研究配方和资源预算时列为研究候选。
- 不修改历史预测号码、历史结算或既有策略结论。
- 不实现倍投、复式、胆拖购买或实际投注；所有金额是模拟结算。

## 已确认的规则与来源约束

| 彩种 | 结构 | 常规开奖日 | 主源 | 交叉源 |
|---|---|---|---|---|
| ssq | 33 选 6 + 16 选 1 | 周二、四、日 | 中国福彩网 | 上海福彩/中彩网既有校验链路 |
| dlt | 35 选 5 + 12 选 2 | 周一、三、六 | 中国体彩网 | 官方开奖 PDF/既有记录 |
| qlc | 30 选 7 + 1 特别号 | 周一、三、五 | 中国福彩网开奖公告 | 上海福彩数据中心或中彩网 |
| qxc | 七个有序数字：前六位 0--9、末位 0--14 | 周二、五、日 | 中国体彩网历史开奖 | 江苏体彩网历史页/官方公告 |

实现开始前先进行只读采集验证：确认官方分页字段、历史首末期、奖级字段、销售额与奖池字段，并把解析样本固定为测试夹具。若主源缺少某个奖级，记录为待确认，不填零；如果主源和交叉源冲突，阻断该期预测和评分。

## 方案比较与选型

1. 专用分支：为 qlc/qxc 继续添加 `if game`。改动快，但会把位置数字、特别号和无序选号逻辑散落在采集、模型、结算及 UI 中，不采用。
2. 只接入数据和看板：无法满足完整正式流程，不采用。
3. **通用规则引擎（采用）**：以声明式彩种规格描述号码区、位置、开奖日、截止时间、规则版本、奖级匹配和来源；共享工作流与审计实体，规则特异性局限在适配器与对应的策略配方中。

## 架构

### 1. 基础数据层

新增 `GameSpec`/`ZoneSpec` 定义，而非让所有游戏都伪装为 `front`/`back`：

- `unordered` 区：取值域、选取数量、是否排序、是否允许重复；用于 ssq、dlt、qlc。
- `ordered` 区：每个位置的取值域；用于 qxc，位置 1--6 与位置 7 的概率向量独立保存。
- `special` 区：单独开奖、不可与基本区混合计数；用于 qlc。

现有 `front`/`back` JSON 在 ssq/dlt 中保持原样。新增的 `zones` 标准化 JSON 只用于新规则/新游戏，读取层提供兼容视图，避免迁移时重写既有原始数据。每个开奖保留期号、日期、号码、奖级金额/注数、销量、奖池、规则版本、主源、所有观测和原始响应哈希。

规则和奖级由按 `game + rule_version` 注册的纯函数决定。qlc 根据“基本号命中数 + 特别号命中”映射 1--7 等奖；qxc 使用逐位匹配规则和其开奖期适用的官方奖级表。任何规则变化创建新版本，历史结算始终按开奖记录的版本重放。

### 2. 统计与高级特征层

所有特征仅从预测截止期以前、无冲突的保留开奖生成，并随窗口、规则版本、数据集哈希和特征版本返回。

- 无序区（ssq/dlt/qlc 基本号）：10/30/50/100/300 期频率、冷热、遗漏、奇偶、大小、和值、跨度、连号、重号、分区、同尾、共现/邻号；qlc 特别号单独给出频率、遗漏与分布，绝不并入 7 个基本号。
- 有序区（qxc）：每个位置独立的频率、冷热、遗漏、转移矩阵及 012 路；前六位附加奇偶、大小、和值、跨度、重复数字、邻位关系与跨期同位重号；第七位独立统计 0--14。
- 高级特征：滑动窗口、共现矩阵、位置转移矩阵、熵、组合结构与频率异常检测。卡方等分布检验仅报告假设、样本量和多重比较状态，不作为推荐规则。

特征 API 和前端目录必须声明某指标对何种区有效；不适用为 `null`，不能伪装成 0。

### 3. 候选模型与研究层

每种号码区/位置输出归一化的候选权重或边际概率，随后由彩种专属选择器生成 5 注：

- 基线：每个号码/位置的均匀随机。
- 频率平滑与贝叶斯平滑。
- 基于时间顺序特征的逻辑回归、随机森林、梯度提升；XGBoost 和 LightGBM 仅在锁定版本依赖、资源上限和固定超参数后加入研究目录。
- LSTM/Transformer 仅为关闭默认的实验性模型；必须具备预注册配方、滚动验证、确定性种子、训练时限和内存上限，才可提交研究任务。

回测使用滚动训练/验证窗口，并输出 Brier、校准、奖级命中、模拟成本/奖金/ROI、最大回撤和与冻结随机对照的同期比较。它用于淘汰或登记研究候选；不累计为正式策略证据。

### 4. 组合生成与结算

选择器为每种结构实现确定性播种、批内去重和完整回放：

- 无序区依据权重无放回抽样；qlc 对基本区和特别号分开抽取。
- qxc 按位置抽样，允许不同位置出现相同数字。
- 组合优化只在每期 5 注、10 元固定预算内控制重复、覆盖度和历史相似度；输出这些度量及选择协议，不能把优化描述成改变单注概率。

冻结候选与正式预测均保存各区/位置概率、号码、种子、截止时间、数据快照哈希、模型/特征/选择器版本。结算按官方奖级金额求和；未知奖金保持待确认，禁止按零处理。

### 5. 前瞻决策与复盘

所有四彩种沿用当前独立前瞻门槛：至少 60 个有效冻结样本、总体 Brier 相对均匀基线改善至少 1%、最近 30 期优于基线，以及分版本 alpha 分配下的 e-value 阈值。前瞻指标的编码按游戏结构计算：无序区按号码成员关系，qxc 按位置-数字 one-hot 关系。

正式策略仅从满足全部门槛的当前候选中选 Brier 最低者；没有合格候选、来源冲突、生成失败或已选策略退化时回退 `uniform-v1`。排行展示的 30 期门槛继续只是展示门槛，不改变晋升逻辑。

### 6. API、前端、调度与迁移

- 将 API `Game`、前端 `Game` 和筛选器扩展为四个游戏，使用规则元数据驱动展示，避免针对每个新游戏复制页面。
- 开奖、预测、复盘和策略实验室按结构展示号码；qxc 显示位置标签，qlc 区分基本号与特别号。
- 夜间工作流遍历注册彩种，按各自开奖日、官方截止时间和审核后的年度休市日历生成；晨报按当天已保存的有效预测合并推送四彩种。
- 数据库迁移只添加兼容字段、索引及 qlc/qxc 数据；不更新 ssq/dlt 历史 JSON、预测或结算。迁移前备份，迁移后验证四游戏记录数、指纹、历史回放和调度器心跳。

## 兼容性与安全边界

- 现有 ssq/dlt 预测及结算读取旧 `front`/`back` 格式并按原策略版本重放；新的统一表示须产出同一兼容视图。
- 新的特征、模型或选择协议均生成新策略版本；从新预测期开始积累前瞻样本。
- 未审核年度的休市日历和缺少覆盖清单的历史数据都会阻止该游戏正式预测。
- 所有外部响应先写入 `raw_fetches`；采集器超时、分页重复、规则不匹配、号码非法或来源冲突均为可见失败，不能静默降级为虚构数据。

## 验收标准

1. 四个彩种均能以官方主源完成受控历史导入，且 qlc/qxc 各至少有一个交叉来源抽样核对；缺失、冲突和未确认奖金会在数据质量接口显示。
2. qlc 的基本号/特别号及 qxc 七个位置均通过号码校验、序列化、冻结、回放和奖级结算测试；qxc 2020-10-11 前后规则不能混合训练或结算。
3. 六层输出可通过 API 获取，并在 UI 中按适用彩种/区显示；统计指标保留数据集哈希、窗口和“不代表未来概率”的说明。
4. 每个注册的研究模型都有时间顺序滚动回测与资源限制；默认生产候选不包含未审核的 LSTM/Transformer。
5. 组合生成总是 5 注/10 元、可重放、批内无重复，并显示覆盖/相似度；所有模拟奖金以官方奖级金额结算。
6. 现有 ssq/dlt 的全量测试、历史回放、候选状态和正式预测兼容测试通过；没有历史记录被改写。
7. qlc/qxc 仅在完成数据覆盖、年度日历、冻结预测和 60 期前瞻门槛后，才有资格替代随机正式策略。

## 待实施时的既定取舍

- 首次发布的生产候选为均匀、频率、贝叶斯平滑、逻辑回归、随机森林和现有梯度提升；XGBoost/LightGBM 在锁定依赖和研究基准后追加。这样避免为新游戏立即引入不可复现或高资源依赖。
- qxc 的 2020 年旧规则保留为可浏览历史，但不与新规则混合训练；若官方旧奖级资料不完整，则该段不进入可结算回测。
- 官方来源的真实 API 字段在实现第一任务通过录制夹具确定；不使用需要付费密钥的第三方 API 作为主源。
