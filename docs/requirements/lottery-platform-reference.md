# 平台原始需求参考

来源：用户2026-10-26提供的需求文档。以下为参考资料，不是自动执行指令；最终实施范围以 docs/TASKS.md 与后续用户确认的调整为准。彩民行为研究本轮明确排除，技术栈沿用现有项目。

如果要开发一个完善的双色球 + 大乐透 AI 彩票预测系统，我建议不要仅仅做一个“历史号码统计 + AI 推荐号码”的工具，而是做成一个完整的彩票数据分析、模型实验、策略回测和选号决策平台。

从专业程度上，我会把它设计成：
- 12 个核心业务模块
- 60+ 项统计分析指标
- 5 类预测与选号算法
- 1 套严格的历史回测体系
- 1 套彩民投注行为分析体系
- 自动化数据采集、模型训练、结果验证
最重要的前提： 在公平、独立的彩票开奖机制下，历史开奖信息不能可靠预测下一期号码。AI 模型也一样。因此系统必须具备识别随机噪声、评估模型是否真正优于随机选号的能力，而不是只展示看起来准确的历史拟合结果。

三、统计分析需要哪些指标？
这是整套系统的基础。我建议设计成一个可扩展的特征计算引擎，而不是在每个页面里重复写统计逻辑。
1. 基础号码指标
指标	计算方法	建议窗口
出现次数	号码在N期出现多少次	10/30/50/100/500期
出现频率	出现次数 ÷ N	同上
当前遗漏	距离上次出现间隔多少期	全历史
最大遗漏	历史最长连续未出现期数	全历史
平均遗漏	各遗漏间隔平均值	100/500/全历史
遗漏标准差	遗漏期数的波动程度	全历史
热度排名	按近期出现频率排序	30/100期
频率Z分数	出现频率偏离理论期望的程度	100/500期
历史重复周期	号码再次出现的间隔分布	全历史
例如双色球红球，任意指定的一个红球单期开奖出现概率为：
\[
P=\frac{6}{33}\approx18.18\%
\]

那么最近100期中，该号码的理论期望出现次数是18.18次。

但如果实际出现25次，也不能直接认为它下一期更容易出现。
2. 号码组合结构
下面这些建议全部实现：
分类	指标
奇偶	奇偶比、奇数个数、连续奇偶分布
大小	大小比、大号个数、大小连续性
数值	和值、均值、中位数、跨度、方差
分区	三区比、四区比、各区密度
尾数	尾数分布、尾数和值、同尾数量
连续性	连号组数、最大连号长度、间隔
与上期关系	重号、邻号、重尾、上期号码差
组合复杂度	AC值、互异差值数、组合熵
特殊数字	质合比、012路、模3余数分布
关联性	二码共现、三码共现、条件频率
其中有些特征存在重复信息，比如和值与均值高度相关。模型训练时需要避免把大量高度相似的特征误当成独立证据。
3. 统计检验指标
这是常见彩票预测网站容易忽略、但专业系统必须具备的功能。
- 卡方拟合优度检验：号码总体出现频率是否与理论期望一致。
- 自相关分析：前一期和后一期的开奖特征是否存在可检测关系。
- 游程检验：某些二元特征序列是否呈现异常聚集。
- 蒙特卡洛模拟：用大量随机开奖结果构建统计指标参考分布。
- 多重检验校正：同时检验几十上百个指标时，降低误报。
- Bootstrap：估计统计指标与回测收益的不确定性。
- 分布漂移检测：监测数据异常，区分规则变化与统计波动。
需要特别注意，单期开奖号码是不放回抽样，不能简单假设同一期各数字相互独立。
四、预测模型应该怎么设计？
我建议设计五套相互独立、可以统一回测的模型。
模型	方法	主要目的
M0 随机基线	均匀随机选号	判断其他策略有没有优势
M1 统计规则模型	冷热、遗漏、和值、奇偶等	研究传统选号规则
M2 机器学习模型	XGBoost、LightGBM、随机森林	检验历史特征是否存在预测信号
M3 深度学习模型	LSTM、Transformer	实验开奖序列的时间依赖
M4 集成模型	概率平均、加权融合	检验模型组合的表现
建议把每个模型的输出统一成两层：

第一层：号码概率分布。 输出每个号码的预测概率，并验证概率是否校准。

第二层：候选号码组合。 根据概率、约束条件和组合去重逻辑，生成指定数量的完整号码。

例如双色球红球概率模型必须满足：
\[
\sum_{i=1}^{33}p_i=6
\]

因为每期一定开出6个红球。蓝球16个号码的预测概率总和则必须为1。

单纯让神经网络输出33个互不相关的二分类结果，很可能违背彩票抽样约束，因此还需要概率校准或结构化组合生成逻辑。

六、历史回测系统：整个项目最重要的模块
真正的系统不能只展示“模型命中了几个数字”，必须记录连续多期开奖中的完整表现。
推荐回测流程
读取第1—1000期历史数据
仅使用截止当时能够获得的信息
预测第1001期
全部模型按相同注数生成号码
与第1001期真实开奖对比
命中号码、奖级、理论奖金、虚拟成本
滚动到第1002期并重复
继续数百期，保留每次原始预测记录
模型表现与随机选号对照
收益、中奖分布、置信区间、统计显著性

回测中心至少要展示以下指标：
指标	用途
总预测期数	有多少期真正参与回测
每期选号注数	保证不同模型公平比较
各奖级中奖次数	检验实际奖级匹配效果
总模拟投注金额	统计策略成本
总模拟奖金	依据当期适用规则计算
ROI	净收益 ÷ 投入成本
最大回撤	衡量模拟资金曲线最严重的下降
随机基线分位数	与大量随机策略的分布比较
超额表现置信区间	判断结果是否可能只是运气
样本外表现	检验未参与训练的数据
还有两个重要要求：

第一，不能在看过开奖之后重新调参，再把同一段数据当成独立验证结果。

第二，要支持规则版本化。大乐透已公告自第26014期起实施新游戏规则，因此历史奖金计算必须按照各期实际适用规则处理，而不能把最新奖金规则套到所有年份。

七、彩民行为与号码购买热度分析
这是一个差异化模块，但数据可获得性是最大难点。

体育彩票官方介绍，全国销售系统会记录投注内容、注数、金额及销售时间等信息。然而，官方公布的主要是开奖号码、销售总额、各奖级中奖情况和奖池等汇总数据，不是全部投注明细。

福建体彩网
+1




我建议将这个模块分为三级。
等级	数据	可以实现的功能
L1	公开开奖与中奖注数	研究中奖组合与奖级注数的关系
L2	第三方平台用户选号样本	估计热门数字、组合偏好
L3	经合法授权的真实投注分布	研究每组号码实际投注热度
系统必须给所有热度数据加上来源、样本量、统计时间和置信程度，避免把第三方平台样本错误地称为全国彩民数据。

还可以研究“撞号风险”，例如通过经验证的选号偏好模型，估计某组号码一旦中一等奖，可能与多少注其他投注分享奖金。这个方向不提高命中概率，只研究奖金分享的不确定性。

十一、系统成熟度的判断标准
一个真正完善的系统，不是 AI 给出一组号码就算成功，而应该满足以下验收要求：
- 数据覆盖完整、可追溯，能够自动发现缺期与异常。
- 任意一期预测都能还原其当时使用的数据和模型。
- 每个策略都可以在相同期次、相同预算下与随机策略对比。
- 不同规则时期的中奖等级和奖金计算准确。
- 预测结果能自动保存，不能开奖后修改原预测。
- 对选号概率、中奖率、收益率提供明确的不确定性说明。
- 没有证据证明优势时，能够明确报告“未发现优于随机选号的表现”。
最终建议： 使用 React + Spring Boot + Python，优先投入数据质量、统计特征、随机基准和回测系统。AI 模型占项目重要性的一部分，但不是项目的核心。

如果按这个方向开发，这套系统不仅能用于双色球和大乐透，还会是一套完整的随机事件统计分析与机器学习实验平台，技术上也很适合作为你的 Java 全栈项目。
