# 模型中心与研究任务

模型中心公共显示模型方案、任务配置/状态、失败原因、数据快照哈希、配方版本及结果。管理员登录后才能提交。提交只冻结数据并排队，不在API进程训练，也不发送微信或创建正式推荐。

## 配置与范围

- 模型从内置14个候选中选择；特征方案随模型固定，不接受代码、路径或任意超参数。
- 训练窗口160、300、500条保留记录；截止期必须存在。训练需要完整窗口，滚动回测另需1–20个目标记录。
- 回测每期模型和均匀基线各5注、10元；模型预算上限10–200元，必须覆盖期数×10，随机对照另有相同模拟成本。训练任务periods=1，不产生投注建议。
- 种子为0–2^32-1整数。金额与期数严格拒绝浮点、布尔及越界输入；配置额外字段拒绝。
- 提交冻结当前修订数据和参数；后续开奖修订不会修改已排队快照。窗口内来源冲突直接拒绝。窗口按保留记录计，不承诺官方连续期数完整。
- 同一时间只允许一个queued或running任务，其他提交返回409。不覆盖旧任务，不自动重试失败任务。

## 本地运行

先备份业务数据库，按认证说明配置管理员并完成迁移：

```sh
backend/.venv/bin/python -m lottery.cli init-db
```

007迁移新增research_jobs表。此轮未替你迁移实际业务库。

另开终端运行独立工作进程：

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 backend/.venv/bin/python -m lottery.cli research-worker
```

只取一个任务后退出可加 `--once`。本轮开发未启动真实研究worker或真实数据训练。普通本地启动脚本不会自动拉起该worker。

工作进程使用共享runtime文件锁，仅支持单主机；多个worker不能并行持锁。数据库唯一活动槽阻止任务堆积。启动时将上次遗留running任务标为失败，释放槽位；Ctrl-C记录失败并退出，强制杀进程后下次启动恢复。不支持分布式主机、自动续跑或在线取消。没有硬性运行时限，模型迭代和任务规模由固定参数限制；长时间运行可停止worker，之后重新提交。

研究进程临时使用该任务窗口/种子，结束后恢复PROTOCOL。API与正式调度须独立进程运行，不得在API中直接调用compute。若排队后模型配方变化，拒绝执行并标记失败，需新建任务。

## 产物与解释

训练保存模型元数据、概率及内容寻址产物ID；回测逐期保存模型产物、Brier、模拟号码与结算及共同期次对比。产物位于runtime/research-models，接口不接受上传、不公开pickle下载或反序列化操作。自定义研究窗口/种子会形成研究配方，不能按默认正式模型协议直接装载或晋升。

回测只用目标期之前的固定窗口，使用当前修订历史，是探索性分析，不能伪装成当时已冻结的前瞻结果。均匀基线仅一条轨迹；本接口不做显著性声明，不等同原有100组前瞻对照。未知奖金保持未知，收益比较仅使用双方完整金额交集。任务失败可能留下此前已保存的内容寻址产物，不自动删除或重用旧任务。

## API

- GET /api/research/models：受支持方案和边界。
- POST /api/research/jobs：服务端认证、Origin及CSRF保护；成功202。
- GET /api/research/jobs?limit=20&offset=0：公共分页任务摘要。
- GET /api/research/jobs/{id}：公共冻结配置、快照及结果；不返回凭据。

任务结果只供研究，不改变候选注册、正式5注、调度或通知。本轮未进行云端部署。
